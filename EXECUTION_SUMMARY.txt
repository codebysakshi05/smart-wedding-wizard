SOLUTION ARCHITECTURE
─────────────────────

Layer 1: Manifest-Based Resolution (Primary)
→ Uses src/data/assetManifest.json
→ Looks up exact paths with correct file extensions (.webp, .avif, .jpg)
→ Guarantees correct files, zero 404 path mismatches

Layer 2: Path Transformation (Secondary)  
→ fixAssetPath() utility wraps all returned paths
→ Global safety mechanism for any path issues
→ Can handle future path structure changes with single update

Layer 3: Error Recovery (Tertiary)
→ handleImageFallback() triggered on image load errors
→ Tries alternatives: .webp → .avif → no-dash variants → premium → fallback
→ Last resort: displays global fallback image

WHAT HAPPENS NOW
─────────────────

When a component requests an image:

1. Getter function called (e.g., getVenueImage)
2. Manifest is looked up for exact path
3. Path is wrapped with fixAssetPath (transformation)
4. Component receives guaranteed correct path
5. Image is rendered with proper extension
6. If image 404s, handleImageFallback tries alternatives
7. Final fallback shown if all else fails
